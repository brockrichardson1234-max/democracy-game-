# 2. Prior findings closed

## 2.1 Bounded I3 substrate evolution — CLOSED

The repair explicitly acknowledges that accepted I3 implemented one configured workstream and a synthesis-conflict-only escalation eligibility rule.

I4 now authorizes only the minimum additive substrate evolution needed for its proof:

- exactly two configured workstream definitions in configuration version `0.4.0-pop0-i4`:
  - the accepted I3 Labor/evidence workstream, unchanged in behavior;
  - one inherited-Housing implementation workstream;
- exact lookup by workstream ID across creation, validation, copy, parse, restore, projection, authority resolution, and coordination validation;
- rejection of unknown, duplicate, ambiguous, missing, or extra workstream definitions;
- no prefix, label, office-ID, array-position, wildcard, or open-ended catalogue routing;
- the accepted I3 synthesis-conflict eligibility rule retained unchanged;
- exactly one new `RECEIVED_ASSESSMENT_ELIGIBILITY` rule for the Housing route.

The Housing escalation rule requires the exact Secretary-authored assessment, exact semantic sections, an explicit transfer, complete Chief-of-Staff substantive receipt, the exact Housing workstream/standing authority, and a typed Chief-of-Staff `RECEIPT` escalation act.

Metadata notice, entitlement, technical retrieval alone, another office's receipt, incomplete transfer, workstream membership, historical indexing, and global artifact existence cannot satisfy eligibility.

This closes the mismatch between the I4 route and the accepted I3 singleton/synthesis-only substrate without generalizing I3 into an unbounded workstream or escalation framework.

## 2.2 Typed lower-owner observation and monitoring evidence — CLOSED

The repair removes ambient adapter read authority.

One closed `LowerOwnerObservationAuthority` now binds:

- the observing HUD institution;
- the one-to-one institution identity binding;
- accepted I6/I7 source configuration hashes;
- exact lower owner/state fields;
- exact project IDs;
- exact permitted record kinds;
- exact claim families and observable fields;
- an effective interval;
- authority and provenance.

The adapter must authorize each substantive lower-owner read separately against that record/project/field scope.

The I2 artifact model is evolved only by an explicit closed union containing the accepted I2 variants plus bounded I4 variants. `HousingMonitoringEvidenceArtifact` contains immutable claim-level lineage including source state field, owner, record kind/ID, project, claim family, field path, typed observed value, source time, observation/as-of time, authority ID/scope, source-record hash, supporting occurrence IDs where applicable, and claim provenance.

Monitoring-artifact creation is an explicit information-owner observation operation. It validates source existence/time, authority scope, configured field access, observed value/hash, and immutable artifact/claim hashes before separately recording Department possession.

Global lower-state existence, historical-index membership, adapter reachability, institution identity binding, or unrelated artifact possession grants no observation authority.

Department artifact possession remains distinct from Secretary notice/entitlement/retrieval/receipt/assessment, Chief-of-Staff transfer/receipt, presidential presentation, and Attention.

Restore validates the historical observation rather than rereading current lower-owner state or rewriting the historical observed value.

## 2.3 Canonical Department handling and supplemental-record provenance — CLOSED

The repair assigns Department handling submissions to an existing canonical owner rather than the stateless adapter.

`pop0.owner.office-operations` gains an append-only `departmentHandlingSubmissions` collection partitioned by submitting office, with I4 submissions restricted to the Secretary-of-HUD partition.

Each immutable handling occurrence binds ID/dedupe identity, kind, submitting office/holder, handling authority, source disposition, source instrument-authorized assignment, source assignment result, exact target institution/request/project/relationship/scope, authoritative time, typed payload, and provenance.

The handling occurrence remains distinct from the lower implementation-owner result. The historical index references the occurrence and may link a succeeding lower transition causally, but does not own either result.

The missing `NONAVAILABILITY_RECORD` now has a real evidence route:

```text
pre-opening Department supplier-search evidence
-> Secretary metadata notice (explicit later operation)
-> scoped entitlement + technical retrieval
-> Secretary substantive receipt of all raw sections
-> bounded assignment/options result
-> separately authorized Secretary supplemental-product authoring act
-> immutable DepartmentSupplementalRecordArtifact
-> canonical SUBMIT_SUPPLEMENTAL_RECORDS occurrence
-> validated lower supplySupplementalWaiverRecords(recordTypes[])
```

The raw supplier evidence is explicitly not itself a `NONAVAILABILITY_RECORD`. The opening monitoring artifact is explicitly not the record. The options memorandum is explicitly not the record.

The qualifying supplemental artifact binds exact raw-evidence identity/hash, all required received source sections, Secretary receipt, producing office/holder, disposition/assignment/result lineage, target institution/request/project/relationship/scope, certification and lineage sections, canonical hash, and provenance.

Only after that evidence and canonical handling occurrence validate may the adapter convert the authorized record type into the accepted lower-level `recordTypes[]` argument.

Live and restore validation reject fabricated/extra record types, changed evidence hashes, cross-office or partial receipts, wrong holder, wrong target/scope, invalid assignment/result lineage, expired authority, future chronology, and a lower worked-route determination lacking its corresponding handling occurrence.
